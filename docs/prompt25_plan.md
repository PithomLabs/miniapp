## Approach

Follow prompt25 §9's twelve steps in order, reusing the established evidence discipline (pre-fix snapshot, identical test bytes overlaid on red/green trees, per-finding digests, never-silent contract amendments). Key decisions:

- **Hygiene before freeze.** Run `gofmt -w` first, verify the diff is whitespace-only (`git diff -w` empty), then freeze the pre-fix snapshot — satisfying both P24-006's "before new evidence" rule and the §9 order. This touches register-bound test files mechanically; old hashes stay valid historically, new hashes are recorded.
- **P24-001 shape.** Follow prompt25 §2's 8-step structure verbatim (decide → predicated withdraw → affected-row check → same-tx audit iff won → commit-on-success-result → typed refusal post-commit), not the review's two-tx alternative. Repeats audit as refused/ineligible, never re-withdraw; quarantined/mismatch/transient/wait/contention/infra paths never withdraw.
- **P24-002 shape.** Add `AND attempt_id = $N` (from the in-hand record) to `transition()`; zero rows → existing Superseded handling. Leave `adoptStale` age-only (already safe; uniformity churn rejected, rationale recorded).
- **Deterministic ordering from the outset (no repetition-as-proof).** POC sources are gone (/tmp cleaned), so both POCs are re-implemented from the §15 trigger descriptions. Passing N repetitions never constitutes the ordering proof; every test forces its order with explicit barriers and asserts order markers on every execution (a small repeat count remains only as a flakiness check). POC-2 is channel/gate-driven and deterministic as specified (per-epoch gates + scripted provider outcomes per flavor). POC-1 needs both orders forced: cancel-first via FIFO row-gate staging (Perform pre-claim read queued first, Cancel UPDATE queued behind, order verified in pg_stat_activity) plus a test-only speculative-insertion gate on the claim INSERT that holds Perform while Cancel runs to completion (joined, not slept), then releases so authorizeTx deterministically reads terminal — required because the fault injector is error-only with no pause support (verified), and permitted as test-only synchronization with zero production changes; authorize-first via a provider gate-channel whose entered signal proves ATTEMPTING committed before Cancel runs, asserting in-flight observation and non-recall wording. Audit invariant: exactly one `effect-withdrawn` per successful `PENDING → CANCELLED` transition; repeats audit as `effect-refused/<reason>` (distinct type, never another withdrawal); quarantined/mismatch/transient/wait/contention/infra paths never withdraw — asserted as exact counts and event types, never mere row existence.
- **P24-005 semantics.** Mirror the choke predicate exactly in `authorizeTx` (gated + persisted-autonomous-trust skips linkage), plus a new manifest check (`Autonomous ∈ tool.TrustModes`, currently enforced nowhere — verified). Missing-approval on confirm trust still refuses; any present hostile approval is fully evaluated (no bypass); terminal invocations never exploit the exception. Additionally, persisted trust is independently validated against the admitted manifest: a trust mode the manifest disallows refuses regardless of the linkage exception, so the exception can never launder an invalid trust mode into an acceptable invocation. The matrix proves denied/expired/mismatched/cancelled approvals cannot be bypassed via autonomous trust.
- **P24-007 minting (exact contract).** The framework-generated UUID is the authoritative attempt ID; a caller-provided `Intent.AttemptID` must never become the persisted ID (`claim()` mints unconditionally). An empty caller field is NOT an error — minting covers it. UUID generation failure or an invalid/empty generated ID fails closed. Intent field retained for wire compat with a deprecation note (removal would churn 20+ literals for no safety gain). Tests prove a caller value (e.g. `"attacker-chosen"`) cannot influence the persisted ID and that successive claims receive distinct framework-generated IDs. Verified safe: no test asserts caller-supplied attempt values and mockcap does not key on attempt IDs.
- **Honest test classification.** Discriminating red/green where the defect discriminates (P24-001, P24-002 ×3, P24-003 deadlock-absence, P24-005 test 3, P24-007 mint, P24-011 mapping); characterization where both sides pass (T5-style legs, opposite orderings, P24-004/008/009/010 docs and guards); green-only never labeled as pairs.

3. **P24-002.** Attempt predicate in `transition()`; audit direct-transition test callers; committed POC-2 across CONFIRMED/FAILED/UNKNOWN with per-epoch gates, SQL age manipulation, direct `Settle`, asserting IDs/state/receipts/mock records (affected-row equivalence via state, documented); red/green.
4. **P24-003.** Replace Settle attribution with a lock-free immutable-column read; prove the complete Settle path takes no invocation lock by enumerating every statement in the tx (UPDATE + audit INSERT + attribution SELECT) plus schema verification — migrations contain zero `REFERENCES` and zero triggers (verified), and no new advisory SQL is added; forced both-order deadlock-absence test with statement timeouts demonstrating Settle never recreates the `effect → invocation` dependency and §4.2 stays effect-lock-only; Settle suite green; red/green (pre-fix deadlocks loudly).
5. **P24-005.** Approval-branch exception (`Required && !(persisted-autonomous && manifest-permits)`), seven matrix tests with a gated+autonomous fixture, red/green where discriminating.
6. **P24-004/008.** Docs only: amended activation trigger (framework-declared requirement + forcing mechanism + X-08 commitment + probe limitation record) in the design note and contract M5 rows; capability-membership prerequisite trigger recorded.
7. **P24-007/009/010/011.** Claim-time unconditional minting (empty caller field is not an error; generation failure fails closed) + non-influence and distinctness tests; guard upgrade via AST (mirrors the established INFO-2 `go/ast` precedent — confirmed smallest durable) with planted-violation control; state-qualified contention message (shared helper only if it doesn't disturb `execution-in-progress`); no-rows → terminal binding mapping in authorize + Settle.
